# Архитектура Backend-части CommaFeed

CommaFeed Server — это Java-приложение на базе фреймворка **Quarkus**, использующее современные стандарты разработки корпоративных приложений (Jakarta EE / MicroProfile).

## Технологический стек (Backend)

- **Язык**: Java 25 (используется Record, современные Stream API).
- **Фреймворк**: Quarkus.
- **База данных**: Поддержка H2, PostgreSQL, MySQL/MariaDB, SQL Server.
- **ORM/Query**: Hibernate ORM (JPA), QueryDSL для типобезопасных запросов.
- **Парсинг RSS/Atom**: Библиотека ROME.
- **Безопасность**: Quarkus Security (архитектура на базе Jakarta Security).
- **Логирование**: SLF4J + Logback.
- **Тестирование**: JUnit 5, Mockito, RestAssured.

## Структура пакетов (`commafeed-server`)

Все исходные коды находятся в пакете `com.commafeed`.

### 1. `backend` (Общие утилиты и корень)
- `HttpClientFactory`: Создает и настраивает HTTP-клиенты (Apache HttpClient) с поддержкой прокси и таймаутов.
- `HttpGetter`: Высокоуровневая утилита для выполнения GET-запросов, обрабатывающая HTTP-ошибки и кэширование (304 Not Modified).
- `Urls`: Константы и методы для работы с URL и ссылками.
- `Digests`: Вспомогательный класс для работы с хэш-функциями (MD5, SHA).

### 2. `backend.model` (Слой данных / Entity)
Содержит JPA-сущности, описывающие схему БД.
- `AbstractModel`: Базовый класс для всех сущностей, содержащий идентификатор (ID).
- `Feed`: Глобальная информация об RSS-ленте (URL, ETag, хэш контента, статус ошибок).
- `FeedSubscription`: Подписка конкретного пользователя на ленту (категория, заголовок подписки).
- `FeedEntry`: Информация о конкретной записи в ленте (ссылка, дата публикации, GUID).
- `FeedEntryContent`: Текст статьи, автор и вложения (вынесено отдельно для дедупликации).
- `FeedEntryStatus`: Связывает пользователя и запись, хранит статус (прочитано/не прочитано, избранное).
- `FeedEntryTag`: Пользовательские теги для конкретных записей.
- `FeedCategory`: Иерархические категории для организации подписок пользователя.
- `User`: Данные аккаунта (логин, email, пароль, API Key).
- `UserRole`: Роли доступа пользователя (USER, ADMIN).
- `UserSettings`: Персональные настройки интерфейса пользователя.
- `Models`: Утилиты для работы с JPA-сущностями.

### 3. `backend.dao` (Слой доступа к данным)
Инкапсулирует SQL-запросы через QueryDSL.
- `GenericDAO`: Базовый класс с реализацией стандартных CRUD операций.
- `FeedDAO`, `FeedEntryDAO`, `FeedEntryStatusDAO`, `FeedEntryContentDAO`, `FeedEntryTagDAO`, `FeedSubscriptionDAO`, `FeedCategoryDAO`, `UserDAO`, `UserRoleDAO`, `UserSettingsDAO`: Специализированные DAO для соответствующих сущностей.
- `Predicates`: Набор предикатов QueryDSL для фильтрации данных (например, поиск непрочитанных записей).
- `UnitOfWork`: Компонент для ручного управления транзакциями в интеграции с Hibernate.

### 4. `backend.feed` (Обработка фидов)
Ядро системы, отвечающее за сбор и обновление данных.
- `FeedFetcher`: Загружает содержимое лент по сети, поддерживает ETag и Last-Modified.
- `FeedRefreshEngine`: Координирует процесс обновления, управляет пулом потоков и очередью задач.
- `FeedRefreshWorker`: Обрабатывает конкретную ленту: скачивание, парсинг и расчет интервала обновления.
- `FeedRefreshUpdater`: Синхронизирует результаты обновления с базой данных (вставка новых записей).
- `FeedRefreshIntervalCalculator`: Динамически вычисляет время следующей проверки ленты на основе частоты обновлений контента.
- `FeedUpdateNotifier`: Уведомляет подключенных пользователей о новых записях через WebSocket.
- `FeedUtils`: Вспомогательные методы для нормализации ссылок и обработки текста.
- `ImageProxyUrl`: Генерирует подписанные ссылки для безопасного проксирования изображений.
- `FeedEntryKeyword`: Обработка ключевых слов в заголовках и контенте.

#### `backend.feed.parser`
- `FeedParser`: Основной компонент для преобразования XML (RSS/Atom) в объекты Java.
- `FeedParserResult`: DTO, содержащий результат парсинга ленты и ее записей.
- `XMLCleaner`: Исправляет ошибки в XML-разметке перед парсингом.
- `EncodingDetector`: Пытается корректно определить кодировку фида.
- `HtmlEntities`: Декодирует HTML-сущности в тексте.
- `TextDirectionDetector`: Определяет направление письма (LTR/RTL) для корректного отображения.

### 5. `backend.service` (Бизнес-логика)
- `FeedService`: Базовые операции с лентами.
- `FeedSubscriptionService`: Управление жизненным циклом подписки (добавление, удаление).
- `FeedEntryService`: Управление статусами прочтения и избранным.
- `FeedEntryContentService`: Низкоуровневая работа с содержимым статей.
- `FeedEntryContentCleaningService`: Очищает HTML от XSS (скрипты, опасные стили) перед отображением.
- `FeedEntryTagService`: Управление метками (тегами) записей.
- `FeedEntryFilteringService`: Обработка правил фильтрации для входящих записей.
- `FeedFaviconService`: Управление иконками сайтов.
- `UserService`: Создание, удаление пользователей и смена паролей.
- `PasswordEncryptionService`: Обеспечивает безопасное хеширование паролей.
- `MailService`: Отправка системных уведомлений и писем для сброса пароля.
- `PushNotificationService`: Отправка Web Push уведомлений браузеру.
- `internal.PostLoginActivities`: Выполняет действия сразу после успешного входа пользователя.
- `db.DatabaseStartupService`: Инициализация схемы и данных при запуске приложения.
- `db.DatabaseCleaningService`: Утилиты для обслуживания и оптимизации БД.

### 6. `backend.task` (Фоновые задачи)
Задачи, запускаемые по расписанию.
- `TaskScheduler`: Планировщик периодических заданий.
- `ScheduledTask`: Базовый интерфейс для всех задач.
- `OldEntriesCleanupTask`: Удаляет старые записи из БД для экономии места.
- `OldStatusesCleanupTask`: Очищает устаревшие статусы прочтения.
- `OrphanedFeedsCleanupTask`: Удаляет ленты, на которые больше нет активных подписок.
- `OrphanedContentsCleanupTask`: Удаляет контент записей, потерявший связь с лентами.
- `EntriesExceedingFeedCapacityCleanupTask`: Удаляет избыточные записи, если превышен лимит на одну ленту.
- `AutoMarkAsReadTask`: Автоматически помечает записи прочитанными по истечении времени.
- `DemoAccountCleanupTask`: Специальная задача для очистки данных в демонстрационном режиме.

### 7. `backend.favicon` (Работа с иконками)
- `FaviconFetcher`: Интерфейс для различных стратегий поиска иконок.
- `Favicon`: Контейнер для данных иконки (MIME-тип, байты).
- `HtmlFaviconFetcher`, `FeedFaviconFetcher`, `RootFaviconFetcher`, `YoutubeFaviconFetcher`, `FacebookFaviconFetcher`: Специализированные загрузчики для разных типов сайтов и сервисов.

### 8. `backend.urlprovider` (Поиск лент на страницах)
- `FeedURLProvider`: Общий интерфейс для поиска URL фида по ссылке на сайт.
- `InPageReferenceFeedURLProvider`: Ищет теги `<link rel="alternate">` в HTML коде страницы.
- `YoutubeFeedURLProvider`: Преобразует ссылки на каналы YouTube в ссылки на их RSS-фиды.

### 9. `backend.opml` (Импорт / Экспорт)
- `OPMLImporter`: Обрабатывает загруженные файлы в формате OPML для массового добавления подписок.
- `OPMLExporter`: Генерирует OPML файл со списком подписок пользователя.

### 10. `backend.rome`
- `OPML11Parser`: Расширение для библиотеки ROME, добавляющее поддержку формата OPML версии 1.1.

### 11. `frontend.resource` (REST API)
JAX-RS ресурсы, обеспечивающие взаимодействие с фронтендом.
- `FeedREST`, `EntryREST`, `CategoryREST`: Основные методы для работы с RSS-контентом.
- `UserREST`, `SettingsREST`: Управление профилем и настройками.
- `AdminREST`: Административные функции (управление пользователями, статистика).
- `ServerREST`: Информация о состоянии сервера.
- `fever`: Эмуляция API сервиса Fever для совместимости со сторонними мобильными приложениями.

## Ключевые механизмы

### Жизненный цикл обновления (Data Flow)
1. `FeedRefreshEngine` периодически запрашивает у `FeedDAO` ленты, требующие обновления.
2. Для каждой ленты создается задача, которую берет `FeedRefreshWorker`.
3. `FeedFetcher` делает HTTP запрос. Если сервер вернул `304 Not Modified`, обновление завершается.
4. Если контент получен, `FeedParser` разбирает XML. `XMLCleaner` и `EncodingDetector` помогают обработать проблемные источники.
5. `FeedRefreshUpdater` проверяет каждую полученную запись. Если GUID записи уже есть в базе для этой ленты, она игнорируется.
6. Новые записи сохраняются в БД. `FeedEntryContentCleaningService` очищает их текст.
7. `FeedUpdateNotifier` отправляет сигнал фронтенду через WebSocket, чтобы новые записи появились в интерфейсе без перезагрузки страницы.

### Безопасность и Доступ
- **Аутентификация**: Поддерживается Cookie (для браузера) и HTTP Basic / Query Parameter API Key (для внешних клиентов).
- **Пароли**: Хранятся в виде защищенных хэшей, никогда не передаются в открытом виде.
- **XSS Protection**: Весь входящий HTML контент проходит через строгий фильтр (библиотека Jsoup с настраиваемым белым списком тегов).
